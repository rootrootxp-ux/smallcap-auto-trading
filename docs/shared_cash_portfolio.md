# 全銘柄共通100万円の現物買いポートフォリオ

`portfolio_engine.py` は全銘柄の5分足を日本時間の共通時間軸に統合し、同じ現金・予約資金・保有簿価を更新します。
MAのみ、VWAP＋出来高、高値ブレイク＋出来高は混合せず、各戦略×スリッページ1円/2円×費用ゼロ/現物手数料込みの12口座を独立計算します。

- 初期現金100万円を全50銘柄で共有、1銘柄30万円上限、100株単位。
- 現物買い専用です。信用取引・空売り・レバレッジ・借入は未実装、信用金利は0円。
- 片道手数料は既定100円＋0bps、ゼロ費用条件も併記。スリッページと2,000円の終値ベース損切りは維持。
- 同日完了取引の両側費用控除後実現損益が口座合計−5,000円以下なら、当日の新規買いを停止。既存保有のexitは継続。翌日も現金は繰り越します。
- 売却代金は帳簿上その時点で再利用可能とする仮定。受渡日・差金決済等の実口座制約は再現していません。
- 証券会社接続・実注文はありません。

## 時刻・順位・株数

5分足のラベルは開始時刻です。すべての前足終値を観測してから、その境界の売りを全件処理し、口座停止判定を行い、買いを処理します。
同時シグナルの優先順位は**銘柄コード昇順**です。現在/将来の勝率・最終損益・未来の値動きを順位に使いません。
同時刻の売り損益はバッチで合算して停止判定するため、同時刻の損失/利益を売るコード順で結果が変わりません。
一度停止した当日の新規停止は、後の利益で解除しません。

株数はシグナル終値＋スリッページと、その時点の未予約現金から固定します。
未約定売りの将来代金を先取りせず、注文代金＋手数料を現金内に予約します。
次足始値で株数を計算し直しません。始値ギャップで30万円を超える場合、または他注文の予約を保護した現金が足りなければ取消します。
ログでは `cash_shortage` / `position_cap` / `missing_bar` 等を区別します。

日中は09:00〜11:25、12:30〜15:20の5分足を使い、11:25足の次の取引可能時刻は12:30です。
クロージング・オークション前の**15:20始値で予定決済**します。将来の欠損を見て「最後に残った足」を選びません。
旧方式の可変最終観測足決済と完全に同じではなく、利益に合わせた時刻最適化でもありません。
シグナル確定と次足始値の境界で遅延なく注文できること自体が仮定です。

## データ欠損と未確定

新方式は全日データを後から見て過去取引を除外せず、時系列に欠損を検知します。
09:00初足がなければその銘柄の当日新規を停止し、次に期待した足がなければ注文を取消します。
欠損区間を飛び越えて、後から見つかった足で約定したことにしません。欠けた価格を補間しません。
既知Openで約定した後に同足Closeが欠けた場合、Open約定まで取り消しません。

保有中の観測が欠けた場合は、当該建玉を未決済・未確定として保持し、口座全体の以後の新規買いを停止します。
当該建玉を後の価格で勝手に決済せず、他の観測可能な保有の決済は継続します。
最終総損益・口座最大DDは空欄となり、現金/簿価/完了取引損益は既知値、最後に観測できた価格による評価額は参考値として残します。
口座DDの参考値 `observed_max_drawdown` は欠損発生前までの評価点のみで、未観測区間や足内高安を通る真のDDではありません。
勝率は完了取引だけから計算し、未決済の勝敗を推測しません。

## 帳簿と出力

すべての評価点で次を検査します。

- 現金＝未予約現金＋予約現金、いずれも非負。
- 現金＋保有簿価（買付代金＋未決済買い手数料）＝100万円＋完了取引の費用控除後実現損益。
- 推定清算価値＝100万円＋実現損益＋評価損益。清算価値には仮の売りスリッページ・手数料を反映。
- 全保有が決済済みなら、現金−100万円＝全売買記録のnet損益合計。

`results/portfolio/` にHTML、summary/trades/orders/equity/daily/positions/input_audit/metadata CSVとindependent_comparison.csvを保存します。
`portfolio_equity.csv` のholdingsは各時点の銘柄別株数・簿価・最後の既知価格・未確定状態のJSONです。
`portfolio_positions.csv` は最終残存建玉です。CSVの空欄は未確定であり0円とは違います。
入力価格は旧独立計算が保存したCSVをハッシュ付きでそのまま使い、共有版だけ別の価格を取り直しません。

## 旧方式との比較・バイアス

旧 `smallcap_auto_v3.py` の銘柄別100万円計算は維持しています。
新旧には資金共有のほか、事後的全日品質除外/時系列処理、取得セッション、終端決済時刻の差があります。
比較を資金共有だけの因果効果と判断しません。独立条件の合算損益は、共通100万円口座の損益ではありません。

現物portfolioモードでは比較用の独立計算も金利0にします。通常independentモードでは従来の仮定金利入力を引き続き使えます。
過去の金利3%の保存成果物を手動でsourceに指定した場合は、比較CSVに旧金利も記録するので、費用前提の違いを考慮してください。
現50銘柄には先読み・生存者・手動プール選択バイアスが残ります。今回の結果は将来の収益性の証明ではありません。

## 手動実行

Actions → Backtest v3 → Run workflow で `simulation_model=portfolio`、`universe=research50`、`validation_mode=standard` を選びます。
既定の `independent` と保存実験 `fixed_conditions` は引き続き利用可能です。
旧レポートの株価取得・独立計算後、同じ保存価格で共有口座12条件を計算し、会計と時系列を検証します。
存在する成果物は失敗時もアップロードし、プログラム不具合・会計矛盾・全条件が未確定で完了口座を検証できない場合はActionsを失敗にします。
一部条件が未確定の場合は集計とHTMLで明記します。Actions成功は全12口座の損益確定を意味しません。

```sh
python -m unittest discover -s tests -v
python smallcap_auto_v3.py --watchlist watchlist.csv --annual-interest-pct 0
python scripts/check_results.py
python scripts/run_portfolio.py
python scripts/check_portfolio.py
```
