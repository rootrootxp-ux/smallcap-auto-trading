# 条件を固定したフォワード・イベントスタディ

この研究は、事前に固定した50銘柄について、将来の固定期間に観測する5分足を保存し、固定したイベント成立後の価格変化を調べます。空売り注文、信用取引、証券口座接続、共有資金ポートフォリオは実装対象ではありません。100株換算の損益は参照値です。

過去の記述研究とは別に観測期間と保存規則を固定しますが、50銘柄を選ぶ際に用いた現在の上場・時価総額・流動性情報による選択の偏りは残ります。将来収益の証明や、実際に空売りできたことの検証とは扱いません。

## 固定する対象と期間

対象は凍結した50銘柄、期間は **2026-11-09〜2026-12-07の20取引日**、最終締切は **2026-12-07 18:30 日本時間（Asia/Tokyo）** です。50銘柄×20日＝1,000個の銘柄・日セルを、データ取得の成否にかかわらず監査対象に残します。

研究IDは `forward-short-events-20261109-v1` です。固定対象・保存規則・締切・ファイルのSHA-256は [protocol.json](../research/forward_study/protocol.json)、日付と保存したJPX公式資料の出典・ハッシュは [calendar.json](../research/forward_study/calendar.json) に記録します。取引予定日の固定は、各銘柄が実際に売買されることや、ベンダーが全足を供給することの保証ではありません。臨時休場・売買停止などがあっても、別の日や銘柄へ黙って置換しません。

| 週 | 固定した取引日 |
| --- | --- |
| 11月9日の週 | 11/09、11/10、11/11、11/12、11/13 |
| 11月16日の週 | 11/16、11/17、11/18、11/19、11/20 |
| 11月23日の週 | 11/24、11/25、11/26、11/27 |
| 11月30日の週 | 11/30、12/01、12/02、12/03、12/04 |
| 12月7日の週 | 12/07 |

週末と11月23日は対象に含めません。銘柄の入替え、観測期間の延長、欠損日の別日への置換、良好な日だけの採用は行いません。取得に失敗しても、対象から消して分母を小さくしません。

イベント判定と費用条件はPR #5のイベントスタディから凍結した [core.py](../research/forward_study/frozen/core.py)、[config.json](../research/forward_study/frozen/config.json)、[watchlist.csv](../research/forward_study/frozen/watchlist.csv)、依存ライブラリの固定ファイルを使います。MA3下抜け、当日近似VWAP下抜け、直前5本比1.5倍超の出来高、直前6本の安値割れ、時間帯の5種類、5・15・30分の観測時間を変更しません。条件の定義は [既存イベントスタディの説明](event_study.md) も参照してください。

## 保存と採用の規則

各銘柄・日について、形式が有効で空ではないデータが最初に永続保存・公開された版を **primary** とします。「有効」は研究用入力として読み取れることを指し、全ての予定足が揃っていることや、その日のデータ品質が良好であることを意味しません。欠損、出来高ゼロ、不正な足などがあっても、品質を理由に初回版をより良い版へ差し替えません。

後の再取得やベンダー改訂は別のrevisionとして保存し、初回版とハッシュ・取得情報を比較できるようにします。主解析にはprimaryを使い、後日得られた完全な価格で初回の欠損を補完しません。取得したというローカル記録だけでは採用せず、永続公開の記録（receipt）によって保存を確認します。receiptの公開時刻はcaptureのGit push成功応答後に記録します。最終採用には、応答受信時刻・capture完了時刻・receipt公開時刻の全てが固定締切以前である必要があります。締切後に公開された取得や改訂を、過去日付の足だからという理由で最終解析へ追加しません。

観測データはコードと分離した `data/forward-event-study-v1` ブランチに追加保存します。通常の公開処理は既存ファイルの変更・削除とforce pushを許可しません。capture公開後のreceipt公開に失敗した場合、receiptのないデータを最終採用したことにはしません。ただし、この追加専用の検査はリポジトリ管理者による履歴書換えまで防ぐものではありません。

データがまだ存在しない未来のセルと、収集・監査すべき時点を過ぎても取得できていないセルを区別します。各日の18:30日本時間より前の未取得セルは `not_due_yet`（pending）、以後は `missing_due`（不足）です。取得済みは、対象取引日と同じ日本時間の日付に公開された `available_on_time` と、後日に公開された `available_late` を分けます。当日公開かどうかと、18:30時点で未取得を不足と数えることは別の区分です。全ての採用には前述の最終締切が適用されます。

開始前や期間途中に、未到来セルを取得失敗と数えません。未到来の品質数値は未評価のままとし、ゼロや不足足数へ置き換えません。期限到来後にprimaryがないセルは、固定グリッドの65足が不足したものとして監査します。品質監査には予定足の欠損・重複・不正値・出来高ゼロなどを残し、架空の価格や出来高で埋めません。

## 評価の時点と状態

最終締切より前の既定動作は、1,000セルの取得・保存・品質・時期の**カバレッジ監査だけ**です。イベント後の収益率、仮定損益、対照との差、信頼区間は公開しません。明示的な `allow_interim` による途中評価だけを例外とし、出力を参考値として区別します。途中結果で閾値、採用銘柄、終了日を変えたものを、当初の固定検証と称しません。

締切後は固定期間をそのまま最終評価します。不足が残った場合は **final_incomplete** とし、不足したセル・足・観測を明記します。日数が足りないことを理由に期間を延長せず、揃った日だけを別の「20日検証」にしません。締切を過ぎたことと、完全なデータが得られたことは別の判定です。

イベント計算は凍結したルールに従い、足を時系列で扱います。欠損の後に過去の取引まで除外する日単位の選別は加えません。局所的な特徴量窓は必要な足が揃えば回復しますが、当日VWAPは欠損した累積部分を知ることができないため、その日の残りが不明になります。欠損した観測の損益はゼロではありません。

## 主評価と信頼区間

主評価は、観測可能なイベントを重みとした平均値と、同条件で対応付けた対照との差の平均です。副次評価として、日ごとの平均を各日等重みで平均した値も区別して示します。イベントが多い日の影響が強い前者と、日数を等重みにした後者を混同しません。どちらも観測できた区間の記述値であり、欠損が値動きや流動性と関係する場合には偏りが残ります。

不確実性は **日付クラスタ・ブートストラップ** で評価します。追加の区間推定は、全時間帯を合算したイベント種類×観測時間×費用条件の指標が対象です。固定シードは **20261108**、反復回数は **2,000回**、指標ごとに観測値のある日が最低 **5日** 必要です。日付を復元抽出し、選ばれた日の全50銘柄・関連観測を一緒に扱います。全指標で同じ日付抽出を使い、同日内の銘柄や重なった観測を独立した標本として抽出しません。固定カレンダー上の欠損日も抽出対象に残しますが、架空のゼロ収益にはせず、平均の有効観測数へ加えません。

反復した平均値の2.5・97.5パーセンタイルを区間端点にします。有効観測がない反復を除いた件数も残します。必要日数を満たさない指標の区間は未算出とし、ゼロ幅の区間を作りません。

95%区間は各指標についてのpointwiseな区間です。複数イベント・観測時間・費用条件などを同時に見る際の多重比較を調整した区間ではなく、区間がゼロをまたがないだけで戦略の優位性や再現可能な利益を認定しません。最大でも20日であり、異なる相場局面への一般化には限界があります。

`time_of_day` は適格な全時刻集合と、その同じ集合の並べ替えを対照にするため、対照への優位性を測る設計ではありません。対応ペア差とその信頼区間はN/Aとします。イベントと対照の全体平均が構造上一致することと、任意のペアの差を区別します。

## 費用・空売り・解釈の制約

費用ゼロと、仮定手数料片道100円・片道スリッページ1円または2円を比較します。100株換算の費用込み参照損益は `(開始始値 − 終端始値) × 100 − 2 × 片道スリッページ円 × 100 − 200円`、収益率の分母は開始始値×100株です。証券会社の実料金や信用保証金に対する収益率ではありません。

足のラベルは区間開始時刻で、時刻tの足の確定と次足始値はともにt+5分という無遅延の理想化です。貸株在庫、貸株料、逆日歩、空売り価格規制、売買停止、板、実際の約定、損切り可能性を再現しません。上場・銘柄選定の制約や、踏み上げ・ストップ高で買い戻せない危険も解消しません。空売りの損失には理論上上限がなく、参照数量による計算を実運用可能額や口座損益と解釈しません。

## 処理の流れと確認事項

処理は「凍結対象・設定の確認 → 保存とreceiptの確認 → 1,000セルのカバレッジ監査 → 評価可能時点の判定 → 許可された場合だけ凍結イベント計算 → 集計・日付単位の区間推定」です。各段階でコード版・固定条件・入力・primary/revision・保存記録を追跡します。

リポジトリのルートで、固定ライブラリをインストールしてから実行します。

```sh
python -m pip install -r research/forward_study/frozen/requirements.txt
python -m unittest discover -s tests -v
python -m research.forward_study preflight --store results/forward-data --output results/forward-preflight
python -m research.forward_study collect --store results/forward-data --output results/forward-capture
python -m research.forward_study audit --store results/forward-data --output results/forward-audit
python -m research.forward_study evaluate --store results/forward-data --output results/forward-evaluation
```

`preflight` は市場へのHTTP要求・損益計算・データブランチへの書込みを行いません。`collect` も開始日前・休場日・16:30より前は自動取得しません。ローカルCLIの保存と、Actionsのデータブランチへの永続公開は別です。receiptのないローカルデータを主評価へ採用しません。明示的な過去日再取得には `collect --date YYYY-MM-DD`、途中の参考計算には `evaluate --allow-interim` を使用できますが、条件変更や勝者選定には使いません。出力は毎回新しいサブディレクトリに保存します。

本番の各HTTP要求は10秒、最大2試行、1回の取得処理は最大2,700秒です。時間予算を使い切った銘柄を取得済みとは記録せず、既に取得した原文を保存して不足を残します。Gitの公開が競合した場合はforce pushせず失敗させ、次の新規checkoutで修復します。プログラム不具合も取得失敗として隠さず、取得済み証拠を可能な範囲で保存してActionsを失敗にします。

Actionsの **Forward Event Study (frozen protocol)** の手動入力は `preflight` / `collect` / `evaluate` です。本番取得・評価はmain上のワークフローから固定コードcommitをcheckoutして実行します。自動評価は対象営業日と12月8日の回復実行だけに限定し、それ以後は明示的な手動再検証を使います。自動取得は対象20営業日の外では行いません。

ワークフローに設定した収集時刻は取引予定日の17:15、評価時刻は19:00日本時間で、収集の下限時刻は16:30です。GitHub Actionsのcron開始やデータ提供元での確定は保証されません。本番の収集・評価にはmain上のワークフローと不変コードcommitの固定が必要で、PR上の事前検査は市場への取得要求やデータブランチへの書込みをしません。mainへの自動マージや、証券会社の認証情報による注文処理は行いません。

8月28日〜9月7日の保存データの追加分析は [事後的参考検証](forward_posthoc_reference.md) として分離しました。将来期間の日数・入力・成績には加えません。
