# smallcap-auto-trading

日本株の小型・中型株の研究用バックテスト v3。証券会社への接続・実注文機能はありません。

## 構成

- `smallcap_auto_v3.py`: 株価取得、銘柄分類、バックテスト、HTML/CSV出力。
- `watchlist.csv`: 対象銘柄のコードと候補名。時価総額・信用取引可否は未確認です。
- `requirements.txt`: NumPy、pandas、yfinance の検証済みバージョン。
- `tests/test_backtest.py`: 外部通信不要の合成データによる自動テスト。
- `scripts/check_results.py`: 出力漏れ・取得失敗を検出する検証コマンド。
- `.github/workflows/backtest.yml`: 手動実行用 GitHub Actions。

日足3か月と5分足30日を取得し、MA、VWAP＋出来高、高値ブレイク＋出来高の3戦略を片道スリッページ1円・2円で検証します。銘柄ごとに資金100万円、建玉上限30万円、100株単位で独立計算します。

## ローカル実行

Python 3.12 を使用します。Linux/macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python smallcap_auto_v3.py
python scripts/check_results.py
```

Windows は Python を導入して `setup.bat`、続いて `run.bat` を実行します。
生成物は `results/` 内に保存されます。`report.html` はブラウザで開けます。

## GitHub Actions での手動実行

1. 変更を GitHub のデフォルトブランチへ反映します。
2. リポジトリの **Actions → Backtest v3 → Run workflow** を選びます。
3. 実行終了後、実行詳細の **Artifacts** から `backtest-results-…` をダウンロードします。
4. ZIP を展開して `report.html` を開きます。CSVと取得できた5分足データも同梱されます。

成果物は14日間保持されます。自動スケジュールはなく、手動でのみ実行します。
GitHub Actions の利用が許可されている必要があります。公開株価取得に API キーや証券口座情報は不要です。

出力CSVは `screening.csv`（分類）、`backtest_summary.csv`（検証結果）、
`trade_history.csv`（仮想売買記録）、`run_status.csv`（銘柄別取得状況）です。
取得失敗時も存在する成果物をアップロードします。元プログラムは取得失敗でも正常終了し得るため、
Actions は別途出力を検証し、不完全な結果なら実行を失敗と表示します。
取引0回は必ずしもエラーではありません。

Yahoo Finance のレート制限・銘柄廃止・データ欠損などで失敗する場合は `run_status.csv` を確認してください。
合成データテストの成功は実データ取得の成功を保証しません。
手数料・信用金利等は含まず、約定と損失上限は仮定です。

## 検証期間・DD・費用比較

HTMLと `run_status.csv` に各銘柄の日足・5分足取得範囲、品質検査後の検証開始・終了、
利用日数、除外日数と全理由、日足を参照して検出した5分足欠落日を記載します。
欠落日の探索範囲は取得5分足の最初から最後の日までで、取引所カレンダーとの照合ではありません。
取得済みでも品質検査後8日未満の結果は参考値として残し、「利用日数不足」と表示します。
建玉上限30万円・100株単位による見送りと、手数料を含む資金不足は別カウンターです。

旧「日次最大DD」は日末残高系列の期間DDでした。現在は正の円額で以下を区別します。

- 日内最大DD：各日の開始資金と各足始値・終値の推定清算価値で計測し、日ごとにピークをリセット。
- 期間最大DD：同じ評価系列で、日をまたいでピークを保持。
- 日末残高系列最大DD：日末決済後の資金だけを使用する従来の計算。

推定清算価値には仮の売却スリッページ・手数料・金利を反映します。
足内の高値・安値を通る連続的なDDではありません。損益とDDが一致するだけでは異常とは判定しません。

毎回、手数料・金利ゼロと、設定した仮定費用込みを独立再計算します。
**双方とも既存の片道スリッページ1円・2円を適用**します。
デフォルトの仮定費用は片道100円＋約定代金の0bps、買い建玉に年3%（暦日数/365、同日も最低1日）です。
実在の証券会社の料金を示すものではありません。税金や貸株料などは未計上です。
費用によって株数、損切り、日次停止とその後の取引が変わるため、単純に同じ取引から費用を引いただけの比較ではありません。

```sh
python smallcap_auto_v3.py --fee-yen 100 --fee-bps 0 --annual-interest-pct 3
```

Actionsの **Run workflow** でも同じ3値を指定できます。負数・非有限値は拒否します。
費用シナリオ名・片道手数料・仮定年利・費用控除前損益・手数料・金利・控除後損益をCSVに保存します。
3戦略×2スリッページ×2費用シナリオで、各銘柄12行です。

約定は前足の終値で判定し次足始値で処理します。最終足始値の決済は事前設定の仮定です。
売買記録にはシグナル足と約定足の時刻を両方記録します（時刻は日本時間の足開始ラベル）。
全日品質検査による日選択は事後的であり、当時の運用を完全には再現しません。
欠損の補完や利益に合わせたパラメーター調整はしていません。

株数はシグナル終値＋スリッページから事前に決定します。次足の実際の価格で建玉上限・資金を超える場合は、全注文を見送る価格ガードを仮定します。次足価格で株数を再計算しません。このガードや始値約定の実現可能性は未検証です。

## 固定条件・別期間・時系列品質処理の比較

Actions → Backtest v3 → Run workflow で `validation_mode=fixed_conditions` を選びます。
このモードでは料金入力欄を含む可変入力を使わず、`research/frozen/config.json` の固定条件を使います。
通常実行は `standard` のまま利用できます。手動実行のみで、定期実行や口座接続はありません。

```sh
python -m unittest discover -s tests -v
python -m research.run_fixed
```

- 基準コード：`1a488e3` のソースを `research/frozen/engine_1a488e3.py` として保存。
- 基準入力：実行40209137371のHTML・CSV・5分足を `baseline_inputs.zip` に保存。
- 銘柄リスト、依存ライブラリの指定、条件、入力のSHA-256を固定。基準204行の損益・取引数・DDを全件再現確認します。
- 全20銘柄×3戦略×2スリッページ×2費用条件を維持。未取得銘柄も行を残し、取引なしとは区別します。
- 別期間は2026-08-28〜09-07（終了は9/8排他）。基準期間9/8〜10/23と重複ゼロを検査します。
- Yahooの実応答で8/27以前は5分足の60日制限、8/28以降は取得可能と確認しました。
  応答に要求範囲外の最新足が付くため、必ず日付を再フィルターします。応答と取得証跡も成果物に保存します。
- 別期間は最大7営業日しかなく、最低8日の条件を満たさない参考検証です。
  noteは基準期間の成績を見て注目した銘柄であり、別期間でも銘柄選択バイアスは解消していません。

比較用の時系列方式は、09:00初足がなければその日を停止し、その後は昼休み以外で5分を超える欠損を検知した時点で停止します。
未約定の買いは取消し、完了済みの取引は残します。保有中の欠損・終値不明・15:25の決済足不足は
架空決済せず「未決済・総損益未確定」とし、その条件の後続取引も停止します。
始値が分かり終値が欠けた足では、終値の欠損を理由に既知の始値での約定まで取り消しません。

時系列方式には、全日事後除外の撤廃に加えて、初足必須、欠損間隔の厳格化、事前設定15:25決済という変更があります。
したがって損益差の全てを事後除外だけの効果とは断定しません。利用日数は「一部でも時系列処理できた日」で、
従来の「全日品質合格日」とは異なります。未決済時のDDは観測範囲だけの部分的な値です。

成果物の `fixed_summary.csv` に全条件の損益・取引数・DD、`method_comparison.csv` に新旧比較、
`causal_events.csv` に停止・取消・未決済の根拠、`candidate_coverage.csv` に取得・品質状況、
`aggregate.csv` に黒字・赤字・取引なし・未確定・未取得の件数を保存します。
独立した戦略・スリッページ条件の合計損益をポートフォリオ損益とは解釈しないでください。

別期間の生応答も `research/frozen/candidate_inputs.zip` に固定しました（取得証跡のUTC時刻を保持）。
既定の固定検証はこの保存応答をハッシュ検証して再現するため、Yahooのローリング60日制限や成果物14日保持期限に依存しません。
再取得の診断だけが必要な場合は `python -m research.run_fixed --refresh-market-data` を使用します。
期間は変わらず、期限を過ぎれば取得不能として記録します。取得範囲外の最新足、全項目空の時刻グリッドを除き、
一部項目のみ欠ける観測は時系列方式で始値と終値の判明時点を分けて扱います。
従来なら全日除外された日に、時系列方式では欠損前に完了できた取引を
`completed_trades_on_retrospectively_excluded_days.csv` に残します。
